## ملاحظات الأداء (تعديل جديد)

المشروع كان بيحمّل React وBabel من unpkg.com، وبيترجم كل كود JSX (٢٦٠٠ سطر) داخل المتصفح
مباشرة عند كل زيارة — ده أكبر سبب في بطء وثقل الموقع. النهاردة اتعمل الآتي:

1. **تحويل المشروع لـ Vite** بدل تحميل React/Babel من CDN وتفسير الكود live في المتصفح.
   الكود دلوقتي بيتبني (build) مرة واحدة وقت الـ deploy، فبيوصل للمستخدم كملف JS جاهز
   ومضغوط (minified) بدل ما يترجم عندك أنت في كل مرة.
2. فصل الكود لملفات: `src/App.jsx` (المكوّن الرئيسي) و`src/main.jsx` (نقطة التشغيل)
   و`src/index.css` (التنسيقات) بدل ما يكونوا كلهم جوه `index.html` واحد ٢٦٠٠ سطر.
3. شيلنا وزن الخط `500` من روابط Google Fonts لأنه مش مستخدم في الكود خالص (بس ٤٠٠/٦٠٠/٧٠٠
   وAmiri ٤٠٠/٧٠٠) — تقليل حجم الخطوط اللي بتتحمل.
4. إضافة `preconnect` لـ `fonts.gstatic.com` (كان ناقص) عشان تسريع تحميل الخطوط.
5. ملفات الـ API (`api/jsonbin.js`, `api/login.js`) ماتغيرتش في المنطق، اتنقلوا زي ما هما
   (Vercel هيتعرف عليهم تلقائي كـ serverless functions).

### إزاي تشغّل/تنشر المشروع الجديد

```bash
npm install
npm run dev      # للتجربة محليًا
npm run build    # لعمل نسخة إنتاج جاهزة في مجلد dist
```

على Vercel: ارفع المشروع زي ما هو، Vercel هيتعرف إنه مشروع Vite تلقائي (لأن `vite` موجود
في `package.json`) ويعمل build صح، وبرضو هيفعّل `api/jsonbin.js` و`api/login.js` كـ
serverless functions زي الأول بالظبط. متغيرات البيئة (`JSONBIN_BIN_ID`, `JSONBIN_MASTER_KEY`,
`ACCESS_CODE`) نفسها زي ما هي، محتاجاش تتغير.

**تنبيه:** الكود اتفحص وتترجم محليًا بـ esbuild للتأكد إنه سليم، لكن معنديش اتصال إنترنت
في البيئة دي عشان أعمل `npm install` كامل وأجرب `npm run build` فعليًا لحد النهاية. لو حصل
أي خطأ بسيط وقت أول build عندك (على الأغلب مش هيحصل)، ابعتلي رسالة الخطأ وأنا أظبطه فورًا.
